## 决策

文件名永远是 `<id>.md`（全 ASCII），改中文名这条路关闭。中文可读性由 `title` 字段、`aliases`、`_meta/labels.yaml` 与 Bases 视图补足。

## 理由

- 文件树只是次要检索面：Obsidian 的搜索、快速切换、Bases 都走元数据；模型侧靠 catalog grep。
- 改名要同步 catalog、双链与 git 历史，是这套系统里第二高的风险动作（仅次于移动）。
- ASCII 路径对 CLI / git / 跨 agent 最稳，代价只是文件树观感。

## 放弃的替代方案

- **中文文件名**：可读性最好，但断链与跨平台编码风险回升。
- **日期-中文标题**：检索友好，但和 id 体系重复，且改名仍会破坏双链。
- **纯中文 id**：与 `id` 唯一性、catalog grep 都冲突。

## 复审条件

- 若 Obsidian 原生支持文件别名（不靠社区插件），重开此决策。
- 若未来出现大量非 DSH 的人工编辑，可评估"标题前缀"折中方案。
