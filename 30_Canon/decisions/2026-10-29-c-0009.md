## 决策

裁判（deepseek-flash）的质量用 **100 条人工黄金集**做回归，主指标是 **precision**，不是 recall；prompt 每次改动递增 `promptVersion` 并重跑同一套评估。人类在 inbox 上的确认/拒绝作为在线反馈标签，但不据此自动改提示词。

## 理由

- **误记不可逆**：漏记可以补录；把错误结论写进 active 并注入，会持续污染后续对话。因此宁少记、不错记。
- **recall 的缺口有业务含义**：黄金集中“知识库自身实现决策”和“未来截止任务”被现有提示词的施工日志/未完成规则排除，若为提 recall 放宽，会把项目施工过程写回记忆层，和 c-0006 / a-0016 冲突。保留标签口径，在报告里解释，不为分数改标签。
- **评估必须可复现**：`predictions` 适配器读取已提交的真实模型输出，CI/冒烟不重复烧 token；`http` 适配器只在明确重跑时调用真实模型。
- **失败不能空转**：provider 断网时连续失败打开熔断，避免持续消耗配额；队列满与 pending 截断只降级并记 warning，原文仍在 raw，下一窗口可重抽。

## 机制

| 项 | 位置/行为 |
|---|---|
| 黄金集 | `_meta/rules/golden.jsonl`，五类各 20 条，46 应记 / 54 不应记 |
| 评估 | `_meta/scripts/eval-judge.mjs`：`fixture` / `replay` / `predictions` / `http`，输出 precision/recall/F1/confusion，`--fail-below` 可作门禁 |
| 已提交预测 | `_meta/rules/judge-predictions-2026-10-29.jsonl`（prompt `2026-10-29.1`） |
| 基线 | precision 1.000、recall 0.522、F1 0.686、accuracy 0.780、typeAcc 0.958；TP 24 / FP 0 / FN 22 / TN 54 |
| 反馈 | `set-status`/`batch-status` 状态变更时写 `_meta/state/judge-feedback.jsonl`（atomId/jobId/promptVersion/from/to/accepted） |
| 熔断 | 连续 3 次失败打开 1 小时 `breakerUntil`，成功清零 |
| 降级 | 队列满丢新 job + WARN；pending 超限保留最近并记录丢弃字符数 |
| 本地评估端点 | `POST /kb/judge/eval`（同源 JSON，`offset`/`limit`），只用于本地 harness |

## 不变量

1. 评估不写知识库，只写 `_meta/state/` 报告与反馈。
2. 黄金集标签只能人工改；改标签必须同时说明原因并重跑评估。
3. 裁判写入仍默认 `inbox`；precision 达标不等于放开自动确认，确认仍由人完成。
4. 任何 prompt 改动都递增版本，旧预测不能冒充新版本结果。

## 复审条件

- 黄金集扩大到 ≥300 条，或新增跨语言/多项目样本。
- 连续两个版本 precision < 0.8，或线上确认率/拒绝率显著恶化。
- 接入 embedding/检索后，若裁判输入形态改变，需要重建黄金集与基线。
