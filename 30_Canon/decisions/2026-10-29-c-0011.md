## 决策

Phase 4 不再新增记忆能力，只收敛已有实现的重复与脆弱点：

1. **JSON 契约**：`kb.mjs append-session --json` 输出 `{ok,created,action,role,file}`；插件优先解析 JSON，中文正则仅作旧版本兜底。
2. **共享 parser**：frontmatter 解析收敛到 `_meta/plugin/kb-panel/shared/frontmatter.mjs`，CLI 与插件共用；布尔、数字、引号数组语义一致。
3. **共享节名**：工作页五个节名收敛到 `shared/work-sections.mjs` 的 `WORK_SECTIONS`，模板、brief、validate 共用一份。
4. **scope 回落**：vault 外会话且目录 slug 为空时返回 `unclassified`，不再默认 `global`；失败即关闭。
5. **会话 id 唯一**：同一分钟新建多个会话时，同时检查文件名与 frontmatter `id`，冲突加 `-2`/`-3` 后缀；`SESSION_ID` 允许可选数字后缀。
6. **遥测轮转**：`access.jsonl` 超过 `access_max_lines`（默认 50000）或 `access_max_bytes`（默认 5MB）时轮转到 `access-<stamp>.jsonl`，不删除遥测。
7. **配置缓存**：插件读取 `_meta/config.json` 按 `mtimeMs` 缓存，改配置不必重载插件。
8. **版本与初始化**：根目录 `VERSION` 是唯一版本号，`CHANGELOG.md` 按阶段记录；`kb.mjs version` / `init` 提供最小运维命令。

## 理由

- **漂移比缺失更危险**：前面阶段已经出现过 CLI parser 与插件 parser 对引号数组/布尔值解释不同、工作页节名三处重复的问题。共享模块让“同一份协议”有单一实现，测试也只需覆盖一份。
- **契约优于日志解析**：中文 stdout 是给人看的，不是 API；插件依赖中文正则会在文案调整时静默断掉。JSON 加成后旧版本仍可用，是低风险迁移。
- **失败关闭**：空目录回落 `global` 会把无关项目的会话错误地绑定到全局记忆；`unclassified` 更符合“判不准就不注入”。
- **遥测不能无限长**：access 是热度来源，但单文件无限增长会让读取变慢、差异变大；轮转而非删除，保留历史审计能力。
- **版本可回答“我跑的是哪版”**：单一 VERSION + CHANGELOG 比在多个 package/schema 里各写一遍更不容易漂移。

## 放弃的替代方案

- **重写 ingest 或删除“过重”代码**：没有故障率数据前盲删会丢掉 raw 追加与去重这两条已经验证的路径；Phase 4 只收敛接口，保留行为。
- **给 parser 加完整 YAML 支持**：引入依赖与解析差异，超出当前单行 frontmatter 需求；继续明确“只支持子集”。
- **每次访问都重读配置**：实现简单但每次裁判/面板请求都多一次磁盘读；mtime 缓存足够。
- **自动删除轮转后的 access 文件**：破坏“不删除遥测”；只轮转、不清理，由人决定归档。

## 不变量

1. `VERSION` 与 `package.json` 版本一致；`kb.mjs version` 只读 VERSION。
2. CLI 与插件不各自维护 frontmatter parser；工作页节名不各自硬编码。
3. `session_id` 续写优先；新建会话的 id 与文件名都唯一。
4. 空目录 scope 是 `unclassified`，绝不回落 `global`。
5. access 轮转后原文件名继续可用；轮转文件不被自动删除、不进入公开快照。
6. `append-session --json` 的 stdout 是纯 JSON；人类可读文案不得混入。

## 复审条件

- 引入真正的 YAML 子集解析器或外部 frontmatter 库时，替换共享模块并跑全部 fixture。
- 同一分钟高并发建会话仍出现 id 冲突，或 `session_id` 续写在轮转/迁移后失效。
- access 轮转阈值不适合实际数据量，导致读热度变慢或轮转过于频繁。
- ingest 故障率测量完成、确认可安全简化时，另开决策再删代码。
