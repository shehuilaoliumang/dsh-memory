## 决策

第三轮复审不再扩功能，只处理 N2/N4/S4/S5 四个残余问题：

1. **loopback 拒绝**：`/kb/*` 的 handler 在 `http-guard.js` 里检查 `req.socket.localAddress`；不是 `127.0.0.1`、`::1` 或 `::ffff:127.0.0.1` 时直接 403，不进入业务路由。
2. **本机令牌**：`index.js` 每次启动生成独立的 24 字节 local token，写入 `_meta/state/http-token`（0600；state 不进 git、不进公开快照）。非浏览器写请求（没有 `sec-fetch-site: same-origin/same-site`）必须带 `x-kb-local-token`；浏览器仍用 `/kb/panel.json` 下发的 CSRF token。`/kb/ui` 仅上报版本，继续豁免。
3. **不盲删 ingest**：保留 raw 追加、接管、role+seq 去重、自检与失败窗口恢复；`test/FAULT-INJECTION.md` 把每类机制映射到现有测试，删掉任一机制至少一条测试会失败。先有故障率数据再谈简化。
4. **FN 复核而非改标签**：22 条 false-negative 逐条记录在 `_meta/rules/golden-fn-review-2026-10-30.md`；知识库实现决策归 `30_Canon/decisions/`，未来截止任务等完成或到期后重评；judge prompt 不动，避免为了 recall 降低 precision。

## 理由

- **浏览器边界与进程边界是两件事**：同源 + CSRF 能挡恶意网页借浏览器写库，但挡不住同机任意进程直接 POST。非 loopback 拒绝 + local token 文件让“随便一个进程”变成“能读当前用户 state 文件或伪造浏览器头”，但不假装是操作系统级鉴权。
- **令牌不能只活在浏览器里**：CSRF token 由 panel 下发，本机脚本拿不到；独立 local token 文件给 CLI/测试一个明确通道，也让拦截行为可验证。
- **删除不是减债的唯一形式**：ingest 的复杂度对应了真实故障场景；没有故障注入证据就删，等于把已验证的恢复路径换成乐观假设。
- **评估指标不能通过改标签变好**：precision 是安全指标；FN 是产品口径问题，应记录原因、等真实需要时再补类型（task/review_after/project scope），而不是放宽裁判。

## 放弃的替代方案

- **只绑定 127.0.0.1**：监听地址由 DSH Host 配置决定，插件不能保证；handler 拒绝是插件能控制的那一层。
- **所有写请求都要求 local token（含浏览器）**：浏览器取不到 state 文件，会破坏 UI；因此按 `sec-fetch-site` 区分浏览器与非浏览器。
- **用 Host header 判断本机**：Host 可伪造；socket.localAddress 更接近连接事实。
- **直接删除 ingest 的接管/自检代码**：见上，先故障注入再决策。
- **修改 judge prompt 提高 recall**：当前 precision 1.000 是安全基线；FN 主要是口径问题，不应以污染风险换召回。

## 不变量

1. 非 loopback 连接的 `/kb/*` 请求一律 403；`/kb/ui` 也不例外。
2. `_meta/state/http-token` 权限 0600，内容不进 git、不进公开快照、不出现在任何 HTTP 响应里。
3. 浏览器写请求只需要 CSRF；非浏览器写请求必须同时通过 CSRF 与 local token。
4. ingest 的接管/去重/自检/恢复机制在故障注入测试通过前不得删除。
5. judge prompt 版本变化必须重新生成 predictions；`promptVersion` 与 `promptHash` 不匹配即拒绝评估。

## 复审条件

- DSH Host 支持绑定地址配置时，改为显式绑定 127.0.0.1，并保留 handler 拒绝作为第二道。
- 出现同用户进程滥用 local token 的真实案例时，升级到操作系统 ACL/命名管道/进程认证。
- 完成 ingest 故障率测量并能用更小实现覆盖同等故障场景时，另开决策删代码。
- FN 中某类真实高频需求出现时，再评估新增 `type: task` 或 `review_after` 字段。
