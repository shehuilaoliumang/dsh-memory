# 跨库当前真相与无后门授权

## 决策

1. **注入前跨库仲裁**：全局库与项目库各自 `validate` 独立，同一 `subject` 可能在两边各有一条 `active`。注入与 `snapshot.injected` 必须先把两边候选合并，按 `newerTruth` 取一条，再做全局 2 / 项目 3 的 source-aware 预算；不能先按单库预算截断再拼接。
2. **授权无环境旁路**：删除 `KB_NONINTERACTIVE_TEST`。`attach --write` 与 `delete` 只认真实 TTY；smoke 只验证非 TTY 拒绝，并额外断言设置旧环境变量也不能放行。成功路径不再由 CI 的隐藏开关覆盖。
3. **项目库 global 泄漏不静默**：非 legacy 项目库中的 `scope: global` active 记忆仍从注入中排除，但 Host 每库告警一次并列出 id；写入层继续由 `allowGlobal=false` 降级。legacy 根兼容，不误报。
4. **触发词按短语**：移除 `记`、`别`、`我的`、`我用` 等单字/泛代词，保留“记住/记一下/别忘/我希望/我要求/我偏好”等可判定短语，避免“笔记/个别/我的天”误触。

## 理由

- 单库 `currentTruthNotes` 只能看到局部；跨库合并后去重才符合“当前真相”的语义。先截断再合并会让赢家被预算挡掉，也会让旧 claim 占据全局配额。
- TTY 不是操作系统安全边界，但“有没有后门”是可验证的承诺。任何环境变量/测试仓库条件都能被同用户 agent 自行设置；保留旁路等于把承诺降级为文案。
- 过滤本身仍需要，因为旧库可能已有泄漏；但静默过滤会掩盖写入层缺陷，告警让数据问题可见。
- 中文分词不可靠，单字触发词的实际误触率高于漏抽成本；用短语换可解释性。

## 放弃的替代方案

- **把 `currentTruthNotes` 直接挪到拼接后**：单库已先按 2/3 截断，合并去重会少条且不补位。
- **只把环境变量改名为“仅测试”**：同用户仍可设置，等于没修。
- **对项目库 global 条目直接报错**：会打断所有注入；当前先告警并排除，等写入层修完再收紧。

## 验收

- `currentTruthEntries`/`pickBySource` 覆盖两种方向的跨库覆盖、无 subject 保留、source 预算独立。
- 注入与 `snapshot.injected` 共用 `selectInjection`。
- 设置 `KB_NONINTERACTIVE_TEST=1` 后 `delete`/`attach --write` 仍拒绝；失败不消费票据、不改 registry/config。
- 非 legacy 项目库若含 global active，注入排除且控制台告警一次。
- 插件 127/127、冒烟 100/100、`node --check` 全过。
