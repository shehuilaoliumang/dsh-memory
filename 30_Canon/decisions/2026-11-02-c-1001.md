# 工作区记忆库的自动授权与迁移边界

> 知识库记忆层重置后的第一条架构决策，编号从 **c-1001** 起：重置前的 `c-0001`~`c-0021` 已随记忆层删除（仅存 git `bdf14e3`），新系列回避旧号，避免「同号不同事」。v1.16 起新工作区自动建库并默认允许记录，v1.18 起文件夹迁移可按 `store_id` 自动重定位；这两处都放宽了「放权需人临场」的默认，因此把边界、审计与收回路径一次写清。

## 决策

**自动建库与自动记录（授权边界）**

- 自动建库 + 自动允许记录只发生在「本机新建」的库：live 会话 cwd、目录像项目、`<cwd>/.dsh-memory` 还没有库。已有库（含克隆仓库自带的库）仍需显式接入，clone 注入防线不变。
- 自动授权可配置：插件配置 `provision.autoWritable`（默认 `true`）。设为 `false` 时自动只建**只读**库，等用户在面板点「允许记录」。
- 用户级 registry 记录授权来源：插件自动授权写 `autoGranted: true`；用户显式 `attach` 会去掉该标记。收回写入用 `kb.mjs --root <库> attach --read-only`（不需要 TTY）或面板操作。

**文件夹迁移自动重定位（信任边界）**

- 自动重绑定需要**双信号同时成立**：
  1. 旧路径已消失（`oldPathAlive === false`）；
  2. 当前工作区目录创建时间与 attach 时记录的 `folderBirthtimeMs` 一致（容差 5 秒）。
- 改名保留目录创建时间 → 自动重定位，保留 `writable` 与 `autoGranted`。
- 复制/克隆得到新的目录创建时间（或旧路径仍在）→ **不自动**；面板显示「检测到一个未确认的记忆库副本」，由用户确认后才重定位。确认迁移保留 `writable`、去掉 `autoGranted`。
- 旧 registry 行没有 `folderBirthtimeMs` 时首次迁移一律走人工确认（fail safe）；插件启动时 `syncRegistryStoreIds` 会为仍然有效、已接入的库补写创建时间。
- legacy vault 仍由插件配置路径绑定，不参与自动重定位；改 slug/scope 不在本决策范围。

## 与历史「授权与破坏同权」的适用范围

重置前的 c-0015 确立了「授权与破坏同权：放权需人临场」。本决策没有推翻它，而是划清两类放权动作：

- **仍需人临场（沿用 c-0015）**：把**已存在/来源不明**的库变成可写（已有库、克隆仓库自带库的首次 `attach --write`，TTY 门禁）；物理删除（两道闸 + 人工密钥）；把单条原子提升为全局（记忆页人工点击）；复制/克隆或旧 registry 行无创建时间时的迁移确认（面板人工点击）。
- **自动授权（本决策）**：只针对插件在本机**新建的空库**——live 会话 cwd、目录像项目、`<cwd>/.dsh-memory` 原本不存在、registry 无记录。这是「给新库一个默认值」，不是「把外部库变可信」；`provision.autoWritable=false` 可关闭，`autoGranted` 标记可审计，`attach --read-only` 可收回。
- **不是放权、只是让旧授权跟随同一目录**：文件夹改名后的自动重绑定（双信号）。它不新增任何信任，只是把已有 `writable` 指向同一份库。

## 理由

- 「新工作区零点击就开始积累记忆」是产品要求，不是权限漏洞；用「只对本机新建库 + 可配置 + 可审计 + 可回收」四条把它限定住。
- `store_id` 只能证明「同一份库内容」，不能证明「同一个目录」——复制一份包含 `project.json` 的库同样会携带同一 `store_id`。目录创建时间是本机可验证的第二个信号，能区分「改名」与「复制」。
- 复制/克隆场景下，人工确认是唯一的信任来源。

## 边界与残余风险

- 若复制时特意保留目录创建时间（如 `robocopy /DCOPY:T`），第二信号可能被欺骗；但攻击仍须「旧路径已消失」。高风险场景可把 `provision.autoWritable` 设为 `false`，或改用人工 attach。
- 跨卷移动会改变目录创建时间 → 需要一次人工确认。
- 自动授权只覆盖该库自己的 `10_Raw`/`_meta/state`，不回写 legacy vault；不改变任何 scope。
- `autoGranted` 是审计标记，不是权限判断依据；权限仍只看 registry 的 `writable`。

## 验收

- 单测覆盖：`autoGranted` 记录与显式 attach 清除、attach 记录 `folderBirthtimeMs`、改名同源可自动、复制且旧路径消失时 `sameOrigin=false`。
- 面板卡片区分「已迁移」与「未确认副本」，确认后才重定位。
- `validate` 0 警告；smoke 自包含夹具不受影响。

## 复审条件

- 若出现自动授权到已有库/克隆库、复制库被自动重绑、或授权无法收回 → 回滚相关逻辑并重开本决策。
- 若用户要求进一步收紧为「所有工作区都必须点击授权」，先评估体验成本再改。
