# 2.3：热度曝光降权与 catalog 驱动注入

> 2.2 把「不常驻热门压制相关/新条目」的产品债记进了 FEATURES §10。2.3 只做其中**可验证且不改默认安全边界**的部分：修正热度被曝光污染的错误、给冷启动一条窄通道、把注入与检索从「每轮读全量笔记」改为「读派生索引」，并让检索按字段权重排序。没有引入 embedding 或服务依赖。

## 背景

- **热度自反馈已实测**：旧全局日志里 `inject`（每轮自动注入）占 99%（257 次中 250 次），read/grep/manual 只占少数；原 `rankMemories` 把两种召回同权，等于「越常被注入 → 越热 → 越常被注入」，记忆一多会固化排序并压制新条目。
- **冷启动死锁**：新原子 heat=0，在固定预算下永远排在热门条目之后，可能长期不被曝光。
- **每轮全读**：注入时 `scanNotes` 逐文件读正文、`access.jsonl` 全量解析，笔记多了是线性开销，也让「注入读 catalog」缺少字段基础。
- **检索质量**：BM25 把 `title + title + summary + tags + scope + body` 直接拼接，长 body 稀释标题/摘要命中。

## 决策

### 热度按召回类型加权（曝光降权）

- `rankMemories`（engine）与插件 `inject-ranking.mjs` 按 access 行 `how` 加权：`inject`（曝光）默认 **0.1**，`read`/`grep`/`manual`（显式需求）全权重 1；`lastAt` 取该条最大时间，30 天半衰期不变。
- 权重可配置（`injectWeight`），但默认值固定在代码里；曝光不再主导排序。

### exploration 槽（冷启动通道）

- 排序完成后，把「最新且从未曝光」的 note 移到**位置 2**（0 基 index 1，保留第一推荐）；每轮 1 个槽，**仅项目 store 使用**（legacy/global 不启用）。
- 只影响注入候选顺序，不改变预算总数与安全过滤；无冷启动候选时不动。

### access 热度聚合缓存

- 插件按 `access.jsonl` 的 **mtime + size** 缓存解析结果（含 `how`）；文件未变时重复 prompt 不再全量重读/解析遥测。缓存只服务读取，不改变遥测写入。

### catalog 作为注入源（派生索引）

- `toRow` 增加 `title`/`scope`/`subject` 字段（分别 clamp 60/40/60 字符）；`fitRow` 在 **300B 行预算**内按 `summary → title → scope → subject` 顺序缩短**索引值**，不动笔记正文。
- 注入优先读 `_meta/catalog.jsonl`（mtime+size 缓存），缺失/损坏回退 `scanNotes`；`subject` 由此进入注入仲裁（此前 scanNotes 路径未带 subject）。
- **规则不变**：catalog 是派生索引，手工改原子后必须 `rebuild`；注入读到的永远是 rebuild 时的一致性快照。

### 检索字段权重与只读深度搜索

- engine BM25 文档改为字段加权：`title×3`、`summary×2`、`tags/scope/body×1`（替代原 `title×2`）。
- 插件新增只读 `GET /kb/search.json?workspace&q&limit`：调用 engine `search`，结果用当前 store 的 scan id 白名单过滤（不信任 CLI 返回路径），**不记录 access**；记忆页新增「深度搜索」按钮与清除（客户端 c40，结果按服务端 BM25 顺序展示，本地输入仍走子串过滤以避免逐键延迟）。

## 边界与残余风险

- **不做 embedding/向量检索**：零依赖、本地可跑是硬约束；中文 bigram BM25 在 ≤3k 规模够用。
- **catalog 需 rebuild**：手工改笔记后不 rebuild，注入会读到旧 summary/title/scope/subject；这与既有索引规则一致，不是新风险。
- **relevance 仍默认关**：2.2 的 `inject.rankMode` 默认 `heat`，2.3 只修正 heat 本身，不切换默认；需 A/B 证据。
- **exploration 仅 1 槽**：只保证「最新未曝光」有通道，不做 ε-greedy/UCB 或多样性约束。
- **深度搜索是只读检索**：不写 access、不改变注入，也不替代记忆页本地子串过滤。
- **多库面仍是 policy 表达**：2.2 已做行为合并，2.3 未做「单库存储」；DSH 适配层仍在插件。

## 复审条件

- 若曝光继续主导排序（如 inject 权重被误设回 1、或 access 行 `how` 缺失被当作全权重）→ 回退并补数据校验。
- 若 exploration 槽挤掉第一推荐、或在 legacy/global 生效 → 收窄为项目 store、保留首位。
- 若注入读到与笔记不一致的 catalog（未 rebuild 却不回退 scanNotes）→ 修回一致性规则并重开本决策。
- 若深度搜索写入 access、泄漏非本店路径、或返回未 scan 的 id → 视为越权，回滚 API。
- 当规模超过 BM25 适用范围、或 A/B 证明 relevance 应默认开启时，重开本决策。
