# 3.0：统一读面与 MCP 第二宿主（结构周期）

> 第 16 轮外审 83 分后确认：剩余约 6 分全在结构性项——多库面真正合并（架构 +3.0）与第二个宿主证明（可继承性 +2.0）。本决策接受一次**不发布的结构周期**：期间只做重构，不发 2.5/2.6，完成后直接发 3.0.0。用户已确认目标宿主为通用 MCP、接受 3–4 周不发布节奏。

## 目标

1. **单一读面**：注入选择、逐条原因、面板快照、全库检索都从 engine 的同一份候选宇宙取数；插件不再自行递归、拼接、分叉。
2. **单次检索**：`workspace=all` 在 engine 内一次完成，不再逐库 spawn `kb.mjs search`。
3. **宿主可继承**：engine 不 import 任何宿主；抽出宿主契约，新增零依赖 MCP stdio server 作为第二宿主并完成集成测试。
4. **零行为回归**：文件布局、frontmatter、registry 格式、scope 语义、写入授权、两闸删除、fail-closed、注入预算全部不变。
5. 完成后发 **3.0.0**，公开快照 + 第十七轮外部复审。

## 非目标

- 不加 embedding/向量检索，不改 `inject.rankMode` 默认值，不做跨库写。
- 不合并物理文件（global/project 仍是各自目录），合并的是**读模型与候选宇宙**。
- 不重写 KbPage UI；客户端只删除重复的多库拼合逻辑。
- 不改公开接口语义：`/kb/*` 请求/响应字段保持兼容（只新增字段）。
- 不引入任何运行时依赖；不发布中间版本。

## 现状问题（依据与位置）

- **多入口**：注入选择在 `_meta/plugin/kb-panel/index.js` 的 `selectStoreCandidates` / `selectInjection` / `injectionManifestFor`；解释在 `_meta/engine/lib/injection-reasons.mjs`；工作页简报在 `_meta/engine/lib/work-brief.mjs`。2.4.1 的 B1/B2 只是把两个入口拉同源一次，结构上仍可再次漂移。
- **多库只是策略合并**：`_meta/engine/lib/context.mjs` 只解析 global + 当前 project；管理页的库列表由插件 `workspaceOptions()` 另行枚举；每个入口各自自扫。
- **全库检索串行**：插件 `/kb/search.json` 对每库 spawn 一次 engine CLI 再合并（`index.js` 路由），库数增长线性变慢。
- **「全部记忆库」仅客户端拼合**：`_meta/plugin/kb-panel/client.js` 并发拉 N 份 panel、uid 加前缀；服务端没有统一快照，其他宿主无法复用。
- **宿主绑定**：Cordis 生命周期、`/kb/*`、Web 客户端、turn 事件、prompt 注入都在 `@local/kb-panel`；engine 可复用但只有 CLI 一种消费方式。

## 决策

### 1. Engine 统一读面

新增 `_meta/engine/lib/read-model.mjs`（纯 Node、零 DSH import）：

```js
createSurface({ legacyRoot, globalRoot, registryFile, cwd })
// ->
surface.workspaces()                 // 全部库的统一 descriptor
surface.view({ workspace })
surface.notes() / surface.catalogNotes() / surface.accessRows()
surface.selectInjection(scope, controls, { query })
surface.injection(...)               // { total, global, project, entries, candidates }
surface.manifest()
surface.notesWithInjection(view, { scope, controls, query, manifest, sessionStores })
surface.snapshotAll(context)          // workspace='all' 的服务端合并快照
surface.search({ workspace, query, limit })
```

- 注入选择/排序/access 权重（现 `_meta/plugin/kb-panel/inject-ranking.mjs`、`catalogInjectionNotes`、`accessRowsFor`、`selectStoreCandidates`）下沉到 engine（`lib/injection.mjs` + `read-model.mjs`），插件只保留 pin/mute 会话控制与 prompt 拼接。
- 缓存（catalog / access / work brief）只在 read-model 一处维护，失效仍按 mtime+size。
- `explainInjection` 的候选与 `selectInjection` 的候选由同一对象提供，单源成为结构保证。

### 2. 服务端统一快照

- `/kb/panel.json?workspace=all` 返回合并 notes（每条带 `workspace/workspaceLabel/uid`），只读、不写 access；客户端「全部记忆库」不再并发拉 N 份 panel。
- 单库视图的 `notes[].injection`、manifest、快照计数保持不变；默认视图 id 与选择器 id 的 legacy/dsh-memory 差异继续在客户端归一（已有逻辑）。

### 3. 宿主契约 + MCP 第二宿主

- `_meta/engine/lib/host.mjs` + `_meta/engine/hosts/README.md`（文档 + 常量/校验函数）：宿主必须提供 `cwd`、session scope、turn 文本回调、prompt 注入出口；HTTP 与 UI 是可选能力。
- 新增 `_meta/engine/hosts/mcp.mjs`：手写 JSON-RPC 2.0 over stdio（零依赖），工具：`kb_context`、`kb_search`、`kb_remember`、`kb_status`、`kb_validate`。写入仍走 engine 命令与 inbox + 人工确认规则，不提供删除/授权工具。
- 集成测试用脚本化 MCP 客户端在临时库运行；并加静态检查证明 engine 无 DSH import。

### 4. 迁移与版本

- 开发期全部改动在 main，运行路径由配置 `surface.unified` 开关（P2 起默认 `true`，parity 通过后保留 `false` 作为 2.x 回退；P4 不删旧路径，CLI/引擎行为不变）。
- 期间 VERSION 保持 2.4.1，不发版、不导出公开快照；完成后一次性 3.0.0。
- 旧路径只在 `surface.unified:false` 时作为回退保留；CHANGELOG/ADR 记录 3.0 的新路径与回退开关。

## 硬闸

1. **Parity**：固定 session + 6 库面板 + 21 次检索，ID 集合与原因 state 完全一致；搜索 ID 顺序、`strategy`、`matchedBy`、`matchLabel`、`matchTerms` 完全一致。面板/注入的**热序**允许因 access 变化而变，但集合必须一致。
2. **单入口**：插件注入路径只调 `surface.injection()`；静态检查/审查确认无第二候选来源。
3. **性能**：5 库 × 300 条合成数据，全库搜索 < 500ms、panel 快照 < 300ms、零 spawn。
4. **第二宿主**：MCP 客户端纯 Node 环境跑通 5 个工具；`grep` 证明 engine 无 DSH import。
5. **安全**：写端点、两闸删除、fail-closed、跨库隔离、公开快照扫描全部原样通过。
6. **零依赖**：engine/plugin 的 `dependencies` 仍为空。

## 回滚

- P1–P3 期间旧路径保留，`surface.unified=false` 可立即回退；发现 parity 失败即停在该阶段，不进入下一阶段。
- P4 删除旧路径前先在临时库跑完整 parity + 行为矩阵；若失败，恢复旧路径并记录原因，不发布 3.0.0。

## 风险

- **注入回归（最高）**：以基线 + 行为矩阵 + 开关兜底；注入集合不一致视为阻断。
- **合并读面误碰写路径**：写路径零改动；任何写相关 diff 单独审查。
- **缓存失效漂移**：缓存只留 read-model 一处，mtime+size 单测。
- **MCP 成本**：P3 首日 spike；超 2 天降级为 `kb host --stdio` 最小宿主，但需保持契约与工具语义。
- **周期长**：期间无发布；每阶段结束汇报 parity/性能数字，不静默推进。

## 复审条件

- 任何注入/搜索结果与基线不一致且未记录 → 回退该阶段。
- 统一视图出现写入口，或合并快照能读到未授权库 → 立即关闭。
- engine 出现 DSH import、或插件重新出现第二候选来源 → 结构目标失败。
- MCP 工具能绕过 inbox/人工确认或删除/授权规则 → 视为越权，下线该工具。
- 性能闸或零依赖被破坏 → 不发布 3.0.0。

## 实施结果（2026-11-04，P0–P3）

- **读面**：`createSurface()` 同步返回 `workspaces/view/notes/catalogNotes/accessRows/selectInjection/injection/manifest/notesWithInjection/snapshotAll/search`；插件单库 snapshot/search 与 `/kb/panel.json?workspace=all` 全部改走该对象；`_meta/config.json` 的 `surface.unified` 默认 `true`，`false` 回退 2.x。核心事实：单库 panel total 13、injection 3；all panel total 21、injection 3、uid 形如 `legacy::2026-11-04-c-1007`。
- **宿主/MCP**：`createHost()` 的 context/search/remember/status/validate 由 `host.test.mjs` 6 条覆盖；MCP stdio 实测 initialize（`dsh-memory-kb` 2.4.1）、tools/list 5、kb_status 返回 6 库与计数；写侧仍 fail-closed inbox。
- **闸门**：`compare-parity.mjs` = 3 content drift / 0 regression（drift 为 c-1007 新增笔记及其 `发布` 命中）；`bench-read-model.mjs` = 5 库 × 300 条，检索约 407ms、快照约 139ms、`spawnFree:true`；check 7 JSON / 9 manifest / 18 engine / 2 locale / 34 JS；插件 187、engine read-model 6、host 6、脚本 17、冒烟 106、validate 14 篇/12+1/0。
- **保留的边界**：只统一读面，不跨库写；MCP 不提供删除/授权；`surface.unified:false` 为回退而非长期并行实现；3.0.0 前不发中间版本与公开快照。

## 3.0.1 补丁（2026-11-04，第 17 轮复审 D1/D2）

- **D1 单一入口补完**：`systemPrompt.context` 不再调用插件本地 `selectInjection`，改走 `createSurface().selectInjection()`；插件本地 `legacySelectStoreCandidates`/`legacyPickBySourceWithControls`/`legacySelectInjection` 明确标注仅 `surface.unified:false` 回退，`injectionManifestFor` 同步降级为回退函数；engine 候选扫描补回项目库 `global` scope 泄漏的一次性告警。提示词、面板、搜索结果现共用同一条候选/仲裁/预算路径。
